Agents Flow Creater by FlameGun 系统泳道图

当前代码行为：从项目事实与需求基线提取工程约束，以真实命令、单写者和风险触发的只读独立 Agent 建立方案到黑盒结果的可验证追踪链。

当前交付规则与验证边界

审查结果：只读独立 Agent 在模块闭环候选或人工主动触发时执行需求稳定性审查；适用模块闭环须完成独立黑盒验收。发现按测试先行修复，全量回归和关键源码变异均纳入最终门禁。

交付编排：单一交付契约把需求基线、计划进度、变更工作集和真实命令绑定为确定性门禁计划；开发迭代使用 quick，已知标准影响的闭环候选使用 affected，高风险、跨模块、共享规划器或未知映射自动升级 full。每个可执行门禁有独立输入指纹；最终聚合校验仅在闭环或完成阶段、底层 receipt 齐备后实时执行，且不为自身或彼此签发 receipt，消除自引用。自动修复最多三轮、同一失败最多两次，禁止削弱测试或修改批准需求来制造通过。

审查与泳道频率：普通代码增量只累计变更文件与证据差量，不启动完整审查；仅在模块形成闭环候选或人工主动要求时审查当前指纹。人工触发可检查中间快照，但不自动关闭模块；审查通过后的代码或配置变化会令结论失效，下一闭环候选必须重审。泳道先判定 swimlane_applicable=true|false，再按 flow_impact=none|changed|uncertain 判定：无适用泳道时无图无门禁；有适用泳道且无变化时保留图内容和哈希，确认变化按稳定候选合并，并在首次下游依赖或阶段交接前至多写图一次；阶段结束只对适用泳道校验新鲜度，系统总览只随系统或跨模块边界变化，避免逐文件、逐提交和按时钟重画。

Token 优化：入口 Skill 已去除重复细节；每次执行先建立最小工作集，组合代码、命令、配置、环境和输入指纹生成缓存键，只有验证器确认完全一致且证据存在时才复用。

验证频率：严格安全正文按触发条件独立加载，默认本地协调不读取签名 bootstrap 与受控租约细节；迭代阶段运行 python3 scripts/validate_skill.py --quick，已知标准影响闭环可用 --affected，发布或未知影响运行 --full。快速检查不能作为闭环、发布或安装验收，默认无参数调用仍等价于完整门禁。

成果优先：先从真实入口跑通最小业务流程，得到可演示、可观测的验收结果；再冻结代码版本、Build ID、验收命令、结果和证据 SHA-256。冻结后才启动非必要门禁、重构、代码质量、性能或体验打磨；每个打磨候选重放冻结验收，发生回归时先恢复最小业务闭环。治理完整或门禁通过不能替代业务成果。

原生 GPT-6 Astra 并列通道：Kimi/DeepSeek 外部调用保持暂停。方案作者与黑盒审查者是两个独立、只读的 Codex 原生子 Agent，调度必须显式固定 model=gpt-6-astra；父/主/子层级不授予写权，协调裁决 Agent/run 始终只读、永不持 writer lease。仅登记的当前实现/维护 Agent 可写，并须是匹配唯一活动模块协调租约的 canonical writer；默认本地协调，严格模式才追加宿主证明。其 Agent ID 与 run ID 必须同时不同于协调裁决者，同一身份不得靠切换角色或 run 自审自写。Dispatcher 也始终只读；独立通过只授权记录结果，不授权 writer 自审/黑盒/验收/裁决/关闭/完成/接受。同候选哈希门禁逐轮绑定最小输入、原生 spawn 结果、Agent/run ID 与输入输出哈希。最多 6 轮，无法同版无缺陷通过则标记 incomplete 或 blocked；子 Agent 自报模型和仅编写未执行的黑盒用例均不能充当验收证据。

模块闭环责任制：每个具备稳定业务能力、独立可测入口/输出和非重叠边界的大功能模块只设一个长期维护子 Agent，闭合需求、设计/流程、实现、定向测试、独立验收、证据日志和后续维护。默认本地模式以封闭 receipt 绑定 Dispatcher、聚合写者、模块维护者和门禁审查者的全局唯一 Agent/run 及输入/输出哈希、版本、Build ID 与 verdict；严格模式才追加宿主可信运行时复核和宿主证明 output result。仅有 spawn receipt、自关闭、自声明完成或同义橡皮图章均不得替代独立验收。跨模块交付先逐模块关闭；schema v2 模块/系统交付包逐字段绑定 canonical authority locator、SHA-256 与精确 role/action/policy，规范化模块集合必须一致；独立原生 GPT-6 SYSTEM_AGGREGATION 写者再生成系统清单并以 output receipt 回显同一 authority binding、绑定规范化候选正文哈希，Dispatcher 仅只读调用全量重验。

失败关闭：根级 AGENTS 使用权威机器策略枚举；交付包总门禁绑定 AGENTS、追踪矩阵、工作集、真实命令、计划进度、自动审查、当前模块 run、完成态 latest/index、多 Agent 与适用前端证据；追踪表坏行不再静默丢弃。

分层自检：python3 scripts/validate_skill.py --quick 用于快速迭代；python3 scripts/validate_skill.py --full 聚合 Skill 包、代码结构、全部 CLI smoke、全量回归、源码变异和泳道脚本语法 6 层检查，任一层失败即整体失败。

明确例外：经用户授权的项目级敏感连接配置仅按需进入独立规则与专用校验；用户明确要求时可只读审查该策略及隔离效果，但不获得写入或传播真实值的权限。默认上下文不展示策略细节，公共模板始终脱敏。

浏览器证据：运行时 DOM 可与服务端入口字节不同，但必须绑定自身哈希和同一浏览器 run；当前入口响应另行绑定文件与响应 SHA-256。动作必须真实点击并验证可见结果，配合 Playwright/Cypress。详细规则见 浏览器验证契约；图中不重复维护解析器和历史修复细节。

M03 实现与持续规范

上游输入：批准的追踪项、设计和验收用例；对外输出：唯一写者先校验当前模块拥有路径，再从真实入口跑通最小业务流程，通过必要受影响验证，并冻结代码版本、Build ID、验收命令、可观测结果和证据 SHA-256；随后生成无回归的打磨候选、真实命令结果、原子同步证据，以及绑定当前需求基线与权限矩阵的模块/系统交付包。下游依赖：风险触发独立验收。

成果先行与精确触发：冻结后才启动非必要门禁、重构、代码质量、性能或体验打磨；每个打磨候选必须重放冻结验收，发生回归时先恢复最小业务闭环，治理完整或门禁通过不能替代业务成果。门禁规划器只读输出，由唯一租约写者 CAS 合并；每个可执行门禁 receipt 绑定当前输入指纹、真实输出及哈希，最终聚合校验只在闭环或完成阶段接收同一交付契约并逐项绑定实际工件，实时执行且无自引用 receipt。迭代使用 quick / affected / full，未知影响自动升 full。移动 Web 运行浏览器移动门禁，原生移动运行 native_mobile_tests，跨端变更同时运行两套门禁；普通用户可见文本不自动启动 UI/UX 原型 Agent。人工触发由独立审查者执行，只要求当前阶段已经到达的业务 receipt 与审查 receipt，不提前触发最终聚合；先判定 swimlane_applicable，再三态判定 flow_impact：无适用泳道时无图无门禁，有适用泳道且无流程变化才运行 swimlane_freshness，changed 稳定候选批量写图。审查当前指纹最多3轮/同错2次。
