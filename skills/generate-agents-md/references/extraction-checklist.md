# 事实提取核心清单

只加载本文件完成默认调查；出现明确触发条件时再读取下方专项文件。不要把专项文件全部预载到上下文。

## 按需路由

| 触发条件 | 再读取 |
| --- | --- |
| 建立需求追踪、计划进度、测试/验收或模块闭环 | `references/extraction-delivery.md` |
| 存在 Web 前端、交互页面或泳道图 | `references/extraction-interfaces.md`；再按需读 `references/browser-validation-policy.md` |
| 存在 Dispatcher、长期模块维护 Agent 或跨模块聚合 | `references/module-agent-governance.md` |
| 扩展工作集或复用历史证据 | `references/evidence-reuse-policy.md` |
| 用户明确要求受控敏感配置，或只读审查该策略 | `references/sensitive-configuration-policy.md` |
| 用户明确选择严格签名/宿主证明，或项目有对应高风险/合规映射 | 调用 `$strict-delivery-security`；默认不加载 |

## 默认调查

1. 从当前目录向仓库根查找生效的 `AGENTS.md`，再查目标子目录是否有更深规则。
2. 用 `rg --files` 和 `rg` 定位 README、依赖、构建、CI、测试、部署、环境配置、入口、接口与现有计划/进度/追踪/日志。
3. 只读取与当前目标和直接影响面有关的文件；未知影响先做最小调查，不预载全仓、历史日志或全部治理文档。
4. 对每条候选硬规则记录：规则、事实来源、适用路径、稳定性、保留/改写/下沉/删除决定。用户明确要求或已验证代码/配置才能成为硬规则。
5. 命令必须来自仓库脚本、包管理器、CI 或项目文档；不得猜测。记录工作目录、参数、选择器和适用条件。
6. 公共模板只保留可公开结构和占位符；真实项目引用必须稳定、必要并经作用域确认。

## 作用域与写入

- 根级只保留全仓共用规则；子级只写差异。局部框架、测试、部署或生成代码限制下沉到覆盖相同路径的子级文件。
- 更新既有规则前建立“原规则/决定/证据/目标位置”矩阵；不得静默删除用户要求或仍有效约束。
- 写前运行统一入口 `python3 scripts/flowctl.py scope ...`（兼容实现为 `scripts/validate_task_write_scope.py`）。项目任务只写项目根或获分配隔离工作树；Skill 维护必须有当前用户请求中的明确授权和唯一精确维护源码根。
- 缓存与直装副本是派生产物，不直接修改；作用域校验本身不能提供 OS 级隔离。

## 权限矩阵与最小输出

- 根模板的紧凑 v2 权限声明必须展开为 `expanded-authority-matrix-v1` 后计算 canonical SHA-256；不得把紧凑 JSON 原文哈希当成权限身份。未知合同、矩阵漂移或未列出的 actor/action 默认拒绝。
- 输出前确认：UTF-8 Markdown、作用域正确、无重复冲突、命令可执行、完成条件可判定、所有占位符符合当前模式。
- 只报告修改范围、事实来源、验证结果和待确认项；大日志、截图和完整 diff 只给项目路径。
