# Role-specific local receipt schema v2

Writable local-coordination roles must use schema v2. Schema v1 compatibility is limited to the read-only gate or adjudicator receipts whose validators explicitly retain it; it is never accepted for an implementation or system-aggregation writer. All JSON objects are strict and closed: duplicate, missing, or extra fields fail.

Every schema-v2 implementation or independent-gate spawn receipt contains exactly the common identity fields plus `read_only`, `authority_matrix_sha256`, `owned_paths`, `baseline_sha256`, `code_version`, `build_id`, and `candidate_sha256`. Hashes are lowercase 64-character SHA-256 strings. `owned_paths` is the exact, non-empty, duplicate-free project-relative ownership row in declared order.

An implementation outer evidence object additionally contains exactly one `implementation_write_proof` descriptor with `lease_id`, `target_path`, canonical project-relative `path`, and lowercase `sha256`. The closed implementation spawn receipt repeats that descriptor as `historical_write_proof`. It proves the completed candidate write against the registry, AGENTS/policy, immutable writer source snapshot, candidate/code/build, closed lease, owned target, and owned paths that applied when the write occurred. It does not grant a current write. A new candidate or proof requires a new implementation spawn receipt; path, inode, content, Agent ID, or run ID reuse fails closed.

The default writable implementation and system-aggregation identities are native `gpt-5.6-sol/medium`. Their invocation evidence binds an immutable local JSONL snapshot to the exact session, target turn, provider, model, reasoning effort, Agent path, and source SHA-256. The source label in a coordination receipt is not a substitute for the raw-log provider. Local Qwen has a separate explicit policy and evidence schema; validators never translate one identity into the other.

Every schema-v2 gate spawn and output is `read_only=true` and repeats the same authority, owned paths, baseline, code, build, and candidate. Output additionally binds the role input/output hashes, baseline version, and verdict. A read-only receipt never carries writer proof or lease fields. Gate receipts, Agent IDs, and run IDs are unique and cannot reuse another role's evidence.

The schema-v2 multi-Agent outer object is the only expected-value source and therefore contains `authority_matrix_sha256`, exact `owned_paths`, and `implementation_write_proof`; validators do not infer them from current files. The implementation receipt repeats the outer proof descriptor as `historical_write_proof`.

System bundles must set `runtime_receipt_schema_version=2`; omission or any other value is rejected because system aggregation is writable. The bundle provides dispatcher and aggregation owned paths plus baseline and candidate hashes. `aggregation_receipt_write_proof` validates the completed output-receipt write against its closed historical proof. `aggregation_manifest_write_lease` separately authorizes the later manifest write through the normal live authorization API. The two descriptors must bind different targets and lease IDs. Historical proof never grants a current write, and a live lease never substitutes for the receipt's historical proof. The candidate payload excludes only the aggregation output receipt locator/hash, preventing a hash cycle while retaining both write descriptors.

Default `delivery-first-local-coordination` validates these closed local receipts without a host verifier. `strict-security` runs the same complete local validation first and only then adds trusted-host attestation; it never replaces or weakens the local checks.
