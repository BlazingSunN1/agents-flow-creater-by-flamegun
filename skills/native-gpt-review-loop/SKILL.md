# Native GPT Sol review loop

Run a bounded `solution-author -> black-box-reviewer -> coordinator adjudication` loop with Codex-native sub-Agents only. Kimi and DeepSeek remain disabled; never route this workflow through an external model API.

## Fixed authority and model

- Spawn each solution/review child with the exact model `gpt-5.6-sol` and `reasoning_effort=xhigh`. Run the read-only coordinator/adjudicator at `xhigh`; route workspace mutations only to the separately leased implementation/maintenance Agent running `gpt-5.6-sol` with `reasoning_effort=high`. If the host cannot create the exact model and effort, mark the gate `blocked`; do not silently substitute or claim completion.
- `solution-author` returns a complete proposed solution or complete revision. `black-box-reviewer` independently authors observable black-box cases and reviews the exact candidate.
- Both children are read-only for the workspace, source code, shared plans, progress, traceability, logs, and evidence indexes. They return structured artifacts to the coordinating Agent only.
- Topology is not authority: no parent, main, or child Agent has inherent write authority. The coordinator/adjudicator run is read-only for workspace and shared-record mutation and only records its decision in host-owned orchestration evidence.
- An Agent may write only after project governance registers it as the current canonical module implementation or maintenance Agent and supplies a unique active module coordination lease for the exact module, Agent/run, target, and owned paths. Delivery-first mode records closed local bindings; strict-security mode additionally host-attests them. Dispatcher and coordinator/adjudicator identities and runs are always read-only and cannot hold that lease. A requested revision must be routed to a different implementation/maintenance Agent identity and run; the same identity cannot switch roles to adjudicate and then write. Parent/child position, a recommendation, or a dispatch message never authorizes mutation.
- The authorized writer must not review, black-box test, accept, or close its own delivery. It may only record the already-passed result of applicable independent gates; it must not independently adjudicate or close the module delivery. Independent review, black-box, acceptance, and completion gates remain different read-only Agent/runs bound to the same candidate, code, and build.
- Do not pass full chat history, credentials, unrelated files, another Agent's reasoning, or implementation self-report as evidence. Give each role the smallest hash-bound input set it needs.

## Dispatch protocol

1. Freeze objective, non-goals, constraints, acceptance criteria, risk, scope version, and a SHA-256 over the normalized scope.
2. Spawn `solution-author` with a new Agent ID/run ID, `fork_turns=none`, explicit `model=gpt-5.6-sol`, `reasoning_effort=xhigh`, read-only instructions, and only the approved input manifest. Require one complete candidate, assumptions, requirement mapping, risk controls, verification plan, and remaining uncertainties.
3. Hash that candidate and spawn a different `black-box-reviewer`, also with `fork_turns=none`, explicit `model=gpt-5.6-sol`, and `reasoning_effort=xhigh`. Bind its input to the same scope, candidate version, and candidate hash. Require complete success, rejection, failure, retry, recovery, permission, and boundary cases plus reproducible defects. Authored cases are not execution evidence.
4. The coordinator checks the same candidate and source facts only for advisory adjudication, records every accepted/rejected finding in orchestration evidence, and routes applicable gates to a different independent Agent/run. Local mode binds the run in a closed receipt; strict mode additionally requires host attestation. It does not mutate the workspace or self-prove independent review, black-box, acceptance, or completion. Majority vote is forbidden.
5. If correction is required, send only accepted defect objects and the current candidate hash back to a fresh or resumed read-only `solution-author`; require a complete next candidate and change map. Route any workspace mutation separately to the currently registered, lease-holding implementation or maintenance Agent. Increment the version and invalidate every earlier reviewer/coordinator pass.
6. Stop after at most six candidate versions. A design loop may emit only `reviewed`, `incomplete`, or `blocked`; `reviewed` is not delivery acceptance. Completion `pass` additionally requires a different independent Agent/run to execute the real black-box/acceptance gates against the same candidate/code/build and retain a closed local receipt, plus host verification only in strict mode. Otherwise emit `incomplete` or `blocked` with the exact gap.

## Evidence boundary

For every child record the actual native dispatch call/result, requested model, role, Agent ID, run ID, input manifest path/hash, scope hash, candidate version/hash, output path/hash, and read-only boundary. Also bind the read-only adjudicator spawn receipt and the separately leased canonical writer spawn receipt; their Agent IDs and run IDs must both differ from each other and from every child/gate identity. Distinct roles must not reuse an Agent ID, run ID, input/output path, file identity, or normalized output.

Delivery-first mode validates a closed, hash-bound project receipt that records the requested native model and reasoning effort: implementation/maintenance uses `high`, while solution, review, adjudication, black-box, and acceptance use `xhigh`. That local receipt is coordination evidence and does not prove actual host runtime identity. Only strict-security mode requires the current host's native spawn result or trusted verifier to corroborate the same fields; if that strict proof is unavailable, record `NOT_MACHINE_VERIFIED` and do not close the strict gate. A child self-report or an unbound coordinator-authored field is never sufficient in either mode.

Keep the final write and independent test evidence separate. Authored black-box cases are test assets, never execution. A valid design/review loop does not replace unit tests, rendered frontend clicks, Playwright/Cypress, black-box execution by a different reviewer Agent/run, hardware evidence, or human gates required by the project. This skill deliberately reuses the canonical generate-agents-md contract instead of copying it: validate `../generate-agents-md/assets/native-review-loop-evidence.template.json` with `../generate-agents-md/scripts/validate_native_review_loop.py`. The public validator accepts an exact closed local receipt in delivery-first mode; strict-security mode additionally requires the trusted host verifier.

## Long-task checkpoints

At every candidate boundary, have the authorized evidence writer persist one immutable checkpoint using the closed `checkpoint_chain` contract in `../generate-agents-md/assets/native-review-loop-evidence.template.json`. Bind workflow ID, the read-only `adjudicator_run_id` provenance field, the distinct `writer_agent_id`/`writer_run_id` provenance, round, scope/candidate/code/build hashes, solution input/output hashes, completed gates, pending defect IDs, nonempty next action, UTC creation time, and the current checkpoint locator/SHA. The adjudicator fields grant no write authority; the writer fields identify the separately leased writer but do not replace lease validation. The first checkpoint must use explicit `null` previous locator/SHA; every later entry must link the immediately previous locator/SHA.

After compaction, interruption, or resume, do not replay chat as state. Require a `codex-native-recovery-result` receipt bound to the same workflow, run, round, chain, candidate, code, and build. Delivery-first mode validates its closed structure, path, hash, and exact binding; strict-security mode additionally requires the host verifier to accept it. Missing, reordered, stale, copied, unbound self-authored, or hash-drifted checkpoints and recovery receipts fail closed. The public validator never accepts a caller-supplied host verifier; only the explicitly private test seam may inject one. Never reinterpret context compaction as acceptance.
